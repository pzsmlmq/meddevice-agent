## v1.0.0 — 2026-11-16 · 首次冻结

**内容**

- `product.schema.json` — 清洗后的产品记录，17 个字段
- `ontology.schema.json` — 概念 9 类、关系 8 种
- `trace.schema.json` — 证据链，支持多跳与阴性证据
- `eval.schema.json` — 评测样本，含防泄漏字段
- `validate.py` — 校验器，含重复节点、悬挂边、跨 split 泄漏三项专项检查
- `samples/` — 四份可直接跑通过的样例

**关键决策**

1. `class_level` 用罗马数字 Ⅰ/Ⅱ/Ⅲ，不用英文字母。原始数据两种混着，归一化在这一层做，下游统一。
2. `class_level_raw` 独立保留原值。证据链展示要给用户看原文，不能给他看归一值。
3. `confidence` 与 `source_clause` 在所有 schema 里都是高优先级字段。证据链完全依赖这两个，后补代价等于重做。
4. `ontology` 里 `relation.confidence < 0.5` 的边不参与多跳推理。宁可少一跳，不要错一跳。
5. `trace.hops[].evidence` 必填。没有依据的跳一律删除，不许留空对象。
6. `eval` 引入 `category_l2_id`，专门用于检测训练/测试/反馈集是否泄漏。

**已知取舍**

- `props` 字段不限制键名。不同 ctype 放的属性不同，硬约束会让扩展变难，代价是需要在本 README 里维护一份属性说明。
- 暂不支持多值 `category_l2`。一条记录理论上可能同时属于两个二级类别（罕见），v1.0.0 只保留主类别，遇到时记在 `pending` 里。

**升级路径**

出现以下情况时必须升版本：

- 加字段 → 升次版本（1.0.0 → 1.1.0）
- 删字段或改字段含义 → 升主版本（1.0.0 → 2.0.0）
- 只改 description 文案 → 不升版本，但要在下方补一行说明
